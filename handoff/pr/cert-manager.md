Related to open-uem/openuem-console#ISSUE (feature request: bulk software updates).

## Summary

Adds the NATS permissions needed by the software update features of the related agent and console PRs to the configuration generated by `scripts/generate-nats-conf.sh`.

## Why

NATS only allows the subjects listed for each user in `nats.cfg`. Without these entries:
- **Agent subscriptions are rejected:** the agent's subscriptions to `agent.listpackageupdates.<uuid>`, `agent.updatepackages.<uuid>` and `agent.wingetsource.<uuid>` fail with `Subscription Violation`. The agent doesn't notice, and the console reports the computer as "not reachable" (no responders).
- **Queued updates can't be shown:** the console can't read the requests queued in AGENTS_STREAM for offline computers, so its Update status page can't show them.

## Changes

| User | List | Added |
|---|---|---|
| `CN=OpenUEM Agent` | `sub.allow` | `"agent.listpackageupdates.> openuem-agent-management"`, `"agent.updatepackages.> openuem-agent-management"`, `"agent.wingetsource.> openuem-agent-management"` |
| `CN=OpenUEM Console` | `publish` | `"$JS.API.STREAM.MSG.GET.AGENTS_STREAM"` |

- The queue group matches the one the agent already uses for its management subjects (ping, VNC, RustDesk, …).
- The queued requests themselves use `agent.update.packages.<uuid>`, which AGENTS_STREAM already covers with `agent.update.>`, so no stream or consumer permission changes are needed.

## Upgrades

Existing deployments get the permissions when `nats.cfg` is regenerated, e.g. when the `openuem-certs` container runs again, and NATS is restarted.

### Note for the published image
`nats.cfg` files generated by the currently published `openuem/openuem-cert-manager` image don't include the console's leader election permissions yet (`$JS.API.INFO`, `$JS.API.STREAM.INFO.KV_leaders`, `$JS.API.DIRECT.GET.KV_leaders.>`, `$JS.API.CONSUMER.CREATE.KV_leaders.>`, `$KV.leaders.openuem`), which this script on `main` already has. With such a file:
- the console's election fails (`Publish Violation "$JS.API.INFO"`),
- the software package database used by the package search is never filled.

Publishing a new image from `main` fixes that.

## Tests

- The script generates a configuration with every new entry exactly once.
- `nats-server` starts with the generated configuration ("Server is ready").
- On a Docker deployment, the agent's subscriptions are accepted and the console's Software updates page reaches the agent. An end-to-end run (console, workers, NATS and a Linux agent in containers) logged no permission violations.
